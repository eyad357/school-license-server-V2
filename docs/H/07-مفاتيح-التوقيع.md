# مفاتيح التوقيع (Ed25519)

**الحالة الآن: التوقيع غير مفعّل.** `electron/license/publicKeys.js` فارغ، والسيرفر بلا `LICENSE_SIGNING_PRIVATE_KEY`. لا أدّعي أن التوقيع يعمل في الإنتاج.

## التوليد (على جهازك، لا على السيرفر العام)
```bash
cd school-license-server && npm run signing:keygen      # ينشئ ./signing-keys/license-signing-{private,public}.pem
```
- **الخاص**: يوضع فقط في متغير Railway `LICENSE_SIGNING_PRIVATE_KEY` (يُقبل `\n` بدل الأسطر) و`LICENSE_SIGNING_KEY_ID=k1`. احتفظ بنسخة مشفّرة في مدير كلمات مرور. **لا Git، لا ZIP، لا برنامج Windows، لا دردشة.**
- **العام**: يُلصق في `publicKeys.js` ثم تُبنى نسخة جديدة:
```js
module.exports = [{ kid: 'k1', publicKey: '-----BEGIN PUBLIC KEY-----\n...\n-----END PUBLIC KEY-----' }];
```

## ما يفعله
الإثبات المرتبط بـ `productId + deviceId` يُحفظ مشفّرًا (`signed-license.json` + `.bak`). إن ضاع `state.dat` واستمر `device-id.json` يُستعاد الترخيص دون إنترنت. أي حكم إبطال/انتهاء/إلغاء من السيرفر **يحذف** الإثبات. المؤقت يُستعاد فقط قبل تاريخه الموقَّع. مرفوض: عبث بالحمولة، توقيع مفتاح مجهول، جهاز آخر، برنامج آخر، حالة غير نشطة (كلها مُختبَرة).

## الدوران
أضف المفتاح الجديد (`k2`) **وأبقِ القديم** في القائمة؛ بدّل متغير السيرفر. التراخيص الموقّعة بـ `k1` تبقى صالحة ما دام `k1` في القائمة؛ إن حذفته لن تُستعاد تلك الإثباتات (تبقى `state.dat` سليمة؛ التأثير على حالة فقد البيانات فقط).
**حدود صريحة:** ساعة الجهاز: يُحمى الرجوع للخلف فقط، لا التقديم للأمام؛ جهاز لم يتصل بالسيرفر قط لا حماية له من الرجوع. حكم السيرفر عند أول اتصال هو المرجع.
